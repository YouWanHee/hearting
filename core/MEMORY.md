# Memory — Unified Store (canonical)

> Canonical subsystem split from `CONVENTIONS.md` (2026-06-23); preserve §7 numbering. Spec: `<artifact-root>/spec/prd.md` (`.agent_reports`, legacy `.claude_reports`). Implementation: `tools/memory/mem.py` and dependency-free `protocol_v2.py`, `sync_v2.py`, `git_exchange_v2.py`, `migration_v2.py`.

## §7. Unified Memory System

> Post-its, durable learning and global profiles share **one portable store**. The agent decides contextually what is worth storing, retrieving, promoting, merging, or pruning. Code owns only schema, scope, lifecycle, pending protection, bounded I/O, telemetry and recovery. Behavioral rules belong in bootstraps, `CONVENTIONS`, `WORKFLOW` or Skills, not memory.

### §7.0. Store Architecture

- **Store:** each server's local SQLite WAL serving truth is `${XDG_DATA_HOME:-$HOME/.local/share}/hearting/memory/memory.db`, with existing `<agent-home>/memory` compatibility. DB, WAL/SHM, replica identity, locks, peer watermarks and FTS/CJK/capsule/topic indexes stay local, outside Git exchange. Schema v7 adds capsules (`headline`, `aliases`, `entities`, `topics`, `artifact_refs`, `canonical_id`) and temporal state (`status=active|superseded`, `superseded_by`) beside the body. Topic/search indexes are derived and rebuildable.
- **Store resolution (R0-R5):** all consumers must use the identical `tools/memory/store_resolve.py` / `utilities/memory-store.sh` contract, without reimplementation. **R0:** return non-empty `MEM_STORE` verbatim, unprobed; empty means unset. **R1:** otherwise inspect `$AGENT_HOME/memory`, `$CLAUDE_HOME/memory`, `$HOME/hearting/memory`, `$HOME/agent_setting/memory`, `$HOME/.claude/memory`, `${XDG_DATA_HOME:-$HOME/.local/share}/hearting/current/memory`, then `${XDG_DATA_HOME:-$HOME/.local/share}/hearting/memory`. Skip candidates whose source variable is empty/unset; deduplicate resolved `memory.db` paths, retaining the first original spelling. **R2:** populated means `memory.db` is a regular file or symlink to one; empty directories, dangling links and directories named `memory.db` do not qualify. Probing opens no DB and creates nothing. **R3:** return the sole distinct populated candidate's original spelling. **R4:** multiple distinct DBs exit 3 with empty stdout and a path-only diagnostic naming conflicts and requiring the operator to select one through `MEM_STORE`; precedence cannot break this tie. **R5:** with no DB, return the first existing R1 directory except managed-current, otherwise the canonical XDG candidate. Empty `hearting/current/memory` is excluded from default new-store/dump-import targets; populated managed-current still participates in R2–R4. Creation retains `mem.py`'s empty-store guard unless `MEM_INIT=1` or non-empty explicit `MEM_STORE` authorizes it. The first real probe/canonicalization error (unreadable parent, symlink loop) aborts with R4's exit-3/path-only failure; ordinary absence and R2 wrong types are not errors. Resolution only compares/returns paths: no move, copy, import or spelling rewrite, since replica fingerprint/store identity binds that spelling. Telemetry resolves independently: non-empty `MEM_WRITE_EVENTS`, otherwise `${XDG_STATE_HOME:-$HOME/.local/state}/agent-memory/write-events.jsonl`; `MEM_STORE` does not relocate `WRITE_EVENTS`. Consumer tests must use synthetic HOME/XDG/telemetry and never stat, read or mutate a live store.
- **Tier and scope:** DB is authoritative; files are on-demand views. Without Git, adapters retain actual project cwd: a runtime sentinel such as `/` cannot collapse distinct non-Git scopes. Real worktrees keep logical-project mapping.

  | Channel | Tier/scope | Synchronization |
  |---|---|---|
  | `/post-it` DB working alias | working/project | `mem note` or `mem add` → SessionEnd `mem sync` |
  | `projects/<cwd>/memory/` built-in file memory | durable/project | Direct writes hard-blocked by `builtin-memory-guard.sh`; SessionEnd absorbs current logical project's stray writes only; explicit `mem migrate --all-projects` recovers/imports across projects |
  | `type=profile` DB records | durable/global | `analyze-user` → `mem add` → `mem sync`; `user_profile/*.md` is a human-readable `mem export` cache |

- **Remote convergence:** Git carries only deterministic immutable `protocol/v2/ops/<prefix>/<op_id>.json`, never live DB/WAL, mutable append logs or correctness-bearing dumps. Shared state is the pure fold of the complete validated operation set; arrival, Git topology, batch order and wall clock give no semantic precedence. Routine sync uses a private dedicated exchange outside project trees and local configuration roots, disables hooks and attributes/filters, and stages only allowlisted protocol objects. Opening a session at home does not make home a project tree: that would exclude all default runtime paths, including the shipped exchange. Home descendants remain eligible; genuinely synchronizing home requires an explicit exchange outside it. The exchange is excluded from agent instruction discovery and creation/editing of project rules, skills, hooks, settings, ignores and attributes. Reads update server-local `last_accessed` without authoring operations; prior/post evidence uses the record lineage's recency, not its live row. Live-row digesting permanently blocked destructive prior evidence after a read and stalled store convergence (2026-08-21).
- **Compatibility dump:** ID-sorted v1 `dump.jsonl` serves old readers/limited import-export, not convergence, routine push or destructive import. Frontier/conflict/tombstone/quarantine/unconfirmed-outbox recovery requires immutable protected v2 objects plus consistent local backup or lossless v2 bundle.
- **Remote enablement and cutover fence:** explicit `MEM_SYNC_REMOTE=1` opts in. Only when canonical is unset, legacy `MEM_DUMP_PUSH=1` selects the same v2 exchange with one bounded deprecation warning; it does not push dumps. Both unset/0 means local-only. Enablement, remote URL, protected ref and exchange path also resolve from user-owned `${XDG_CONFIG_HOME:-$HOME/.config}/hearting/memory-sync.json`, overridden field-for-field by environment. Shared policy reaches siblings lacking environment-default settings, without extra authority. Exchange requires either proved fresh v2 or a completed sealed seed epoch, **and** a verified active v2-only old-writer fence. Nonempty legacy, unseeded or unfenced stores refuse before render/fold/push/confirmation/watermark advancement.
  `mem migration` local transitions require sealed inputs, explicit `--apply` and matching `--expect`; they cannot discover or authorize a live roster, credentials, protected ref or all-server rollout. Snapshot seeds include complete captured ancestry, bind reservations/objects in one immediate transaction, and refuse post-snapshot tails or roster namespace mismatch before reservation. Rotation may retain exact captured operations from a sealed snapshot's verified inactive predecessor chain; new seeds bind current replica, and unrelated authors/namespaces refuse before reservation. Snapshot seals exact compatibility graveyard bytes: only proved absent-record entries become prior-state/tombstone seeds; absence alone implies no deletion. An absent record's sole tombstone blocked only by local access-recency drift may be descendant-reseeded only with agreeing exact legacy/transactional graveyard evidence and all other prior fields matching; other drift, concurrency and pending transitions refuse. Delta drain seals exact interval and delta-seed manifest.
  Rollback preparation holds a durable writer barrier and requires a verified complete bundle: protected-ref proof, every active replica's pre-cutover artifacts/phase receipts, immutable object union, unconfirmed set, normalized state and preserved graveyard sources. Export refuses loss. Apply requires a self-digested local target request, fresh target backup and atomic verified projection install, with crash-retryable sealed target/install evidence. Close imports exactly one canonical apply receipt per active replica, then commits the complete bundle digest and removes old-writer triggers using DB-issued closed evidence. Terminal mode stays fenced: only verified old v1 writing resumes; current v2 stays closed until new cutover.
- **Harness integration:** automatic lifecycle belongs only to interactive user-facing main sessions (D-42). `mem inject --hook` may expose bounded working/durable/profile summaries at SessionStart; repeating start events on resume/clear/compact may remain opt-in. Each eligible main prompt runs the capsule probe/receipt contract in §7.4–§7.5. Main SessionEnd syncs current project under the remote flag contract; bounded nonzero sync is reported without suppressing bounded curator fallback. SessionEnd and turn-counter triggers may launch a no-tools distiller agent through `mem-distill-dispatch.sh`, keeping all D-41 controls. Automatic additions declare exactly one purpose: `decision`, `user-correction`, `unresolved-obligation`, `artifact-pointer`; artifact knowledge uses pointer plus retrieval reason, not duplicated summary. Registered dispatches, loops, title workers, distillers/curators and native subagents never run prompt probes, automatic injection, distill counter advancement, exit sync or curator launch. `builtin-memory-guard.sh` confines DB writes to `mem`; hook registration is adapter-native.
- **Post-curation completion:** after the session-end curator attempt, the main completion controller runs one bounded `mem sync --json`. It retains initial-sync/curator/final-sync outcomes separately. Final failure preserves local records, outbox and captured transcript marker without re-extraction. `MEM_POST_CURATION_SYNC_TIMEOUT` defaults to 60 seconds (finite 1–300); children stay in the existing completion process group. D-42 worker markers remain silent no-ops; this stage belongs to main, not model worker/applier. Remote opt-in/fence and local-only default remain. Detached launchers may discard stderr, so final failure also writes one private atomic latest-failure receipt per runtime under `${XDG_STATE_HOME:-$HOME/.local/state}/agent-memory/post-curation-failures/`: at most three 4-KiB files, typed status/time/hashed cwd/session, no bodies or remote URLs. Bounded diagnostics remain available; native hook return proves no remote confirmation.
- **Automatic output validation:** explicit tool-selection runtimes request empty built-in **and** MCP surfaces; a fixed denylist is insufficient. Unsupported runtimes report checked-fallback limits. Automatic appliers validate the entire JSON-lines batch before any memory command. Existing empty/whitespace output or exact sole `{"action":"noop"}` is valid no-action. Missing output, malformed/prose, unsupported shape/action and snapshot-allowlist violation are typed failures: no commands, captured frontier/retry-strikes unchanged. Command failure stops later actions, retaining successful local actions and frontier. These failures never force marker advance. Manual compatibility does not weaken this contract; model/effort, isolation, finite timeouts and admission limits remain.
- **Distillation frontier:** one `mem distill --capture` captures displayed delta plus opaque bounded source/session/store-bound token. `--advance-capture TOKEN` closes only that window, comparing the starting marker under per-session lock and atomically advancing to captured last UUID without rereading live transcript. New messages remain pending; stale capture cannot rewind newer markers. Tokens hold identity/boundaries, no conversation text. Explicit `--advance` stays supported; periodic curation has no transcript marker.
- **CLI:** alongside record/lifecycle/export/import/curator commands: `recall-gate`, `topics`, `supersede`, guarded `activate`, `conflicts`, `show-conflict`, agent-authored `resolve`. `supersede <old> --by <new>` removes old from default recall/injection while retaining both bodies. Legacy-source `migrate` defaults to current project; cross-project recovery requires `--all-projects`. Operator `migration` uses sealed manifests and contained operator-selected artifacts; mutations are dry-run unless both `--apply` and current `--expect` digest are supplied, with no implicit live roster/credential/store/ref authority. Exception: `migration join` requires a provably empty store (no records or v2 operations); one checked leaf seals a fresh epoch and activates its fence, deriving stable epoch from replica/protected ref for idempotent join. Existing stores need sealed-seed cutover.
  Operator `sync --exchange-only` skips native import, expiry/lifecycle, standalone index rebuild and compatibility dump export/commit, reporting skipped phases. It retains store identity, remote policy, readiness, fence, path, validation, fold and confirmation guards. Valid remote operations may update serving/protocol state: it is not read-only. Disabled remote stays local-only and still skips those phases. Ordinary/automatic sync defaults remain. `sync --json` reports versioned `not-configured|local-only|queued-offline|fetched|folded|conflict|quarantined|push-retry-exhausted|remote-confirmed|hard-failure` and phase outcomes. Exit 0: local health, no unmet remote obligation/warning; 1: safe local writes but remote/deferred/conflict/quarantine/retry work remains; 2: integrity/protocol/path/rewind/fence/unsafe-migration failure.
- **Periodic curation:** default off; nightly `utilities/mem-periodic-curate.sh` requires `MEM_PERIODIC_CURATE_ENABLE=1`, otherwise complete no-op like `MEM_DISTILL_ENABLE`. One cron firing dispatches eligible projects sequentially through ordinary D-41 slots/project locks and finite project/run timeouts. It is exempt from the rolling start budget, designed for session-hook fan-out (v18's 216-worker incident): that budget silently skipped nightly batch tails (2026-08-13). DB eligibility maps decodable session cwds to project keys, deduplicates per origin, keeps origins with active records, then orders soft-ceiling-exceeded first and active count next. No directory-list eligibility or session-event fan-out. Without conversation evidence `reattribute` is excluded and deterministically denied (the first evidence-blind curator absorbed 40 foreign records). Worker/registered/dispatch-child contexts refuse under D-42; this mode cannot advance markers. SessionEnd curate remains the backstop.
- **Curator/D-18, D-35, D-40:** `curate-snapshot` exposes active project records plus destructive allowlist. Guarded `supersede` may relate two allowlisted active records without deleting history; profile, pending-delivery, cross-scope/project, nonexistent and cyclic relations refuse. The no-tools model emits action JSON; scripts execute validated argv with `shell=False`. Agents own semantic decisions; scripts only validate shape, visibility, identity, transactions, pending/graveyard protection and bounded lifecycle. Keyword/category/confidence/fixed-phrase semantic judgments are prohibited. Unconsumed pending handoffs remain protected until explicit `consume` (§7.5).

Prompt counters dispatch increments without waiting for the model in the synchronous hook. The main finite controller retains worker exclusion, per-session concurrency, model timeouts and process-group cleanup. Receipt proves only launch, not apply/remote confirmation. Direct calls stay synchronous; SessionEnd joins the increment before its final curate, retaining sync/curator lifecycle.

§7.1–§7.3 govern semantic/mechanical mutation; §7.4 governs agent retrieval.

### §7.1. Semantic Decisions Belong to the Agent

The acting agent judges usefulness, durability, non-obviousness, recovery elsewhere, staleness and ephemerality. There is no deterministic promote/skip classifier. Automatic distillation's four purposes (§7.0) bound ingress **after** judgment: code validates the declaration, never infers it. Manual memory follows its owning capability.

### §7.2. Write Mechanics and Deduplication

- Inspect visible memory before writing; prefer its canonical record over an obvious duplicate. Fuzzy similarity supplies candidates, not verdicts. Artifact pointers hold current path plus why/when to retrieve, rather than replicated prose.
- Populate concise headline and bounded aliases/entities/topics for capsule/topic retrieval; read full bodies on demand. Manual `mem add` should specify `--headline`/`--alias`/`--entity`/`--topic`; empty capsules cannot appear in capsule-first recall/candidates. `write_record` adds body file paths, commit hashes, backtick identifiers and ID-shaped tokens (e.g. `D-40`, `rt-*`) to entities by merge-only mechanical extraction (D-40), not semantic judgment or a substitute for authored headline/aliases/topics. No capsule fields and no extracted tokens produces one advisory stderr line from `add`/`note`, without blocking.
- `supersede` preserves changed decisions as auditable history with one active canonical read path. Guarded remove/merge preserves recovery metadata when the agent judges a record stale. Capacity/similarity are signals; curator chooses consolidation.
- Every semantic mutation must use one `BEGIN IMMEDIATE` for semantic/graveyard changes, replica-counter allocation, exact canonical operation and transactional outbox. Unsupported paths refuse. Local commit is durable through offline/failed exchange, without rollback.
- Private installation evidence outside `memory.db` binds active replica ID. A moved/copied DB with mismatched evidence remains diagnosable but cannot author/sync remotely until explicit `mem replica rotate --reason …` creates an activation boundary; predecessor operations stay unchanged.
- Preserve full concurrent variants. A total key may choose provisional serving state, not semantic resolution. Default injection/candidates/recall show bounded conflict IDs/index only; `show-conflict` shows all labeled variants. Only agent-authored `resolve` descends all maximal heads.
- DB `links` may hold `[[name]]`; insertion mechanically indexes FTS5. `MEMORY.md` is a legacy view.

### §7.2.1. Blocked-history diagnostics

Resolution requires **every affected record** to have exactly one accepted, valid, unblocked, nonpending, nonconflicting final head covering it and truly descending the blocked operation. Different records may have different explicit put descendants or §7.2.2 final tombstones; one unsafe head keeps the entire operation active. One valid final descendant covering all records remains supported. Deletions require an evidenced effective tombstone for each deleted record; blocked/unevidenced deletion cannot resolve prior diagnostics.

Historical-inert diagnosis of a blocked-prior-evidence tombstone requires verified sealed migration membership/evidence, exact seed coverage and verified snapshot contents proving no prior body/state for **all** affected records. Each record's sole operation/final head must be that parentless nonpending blocked tombstone, without later decision, pending state or conflict. Missing/corrupt/incomplete/unsealed reader-local proof keeps active/unsupported status. This is read-only diagnosis, not deletion recovery or semantic resolution. Preserve raw operations, original blocked reasons/counts, bodies, pending flags and history. Opt-in `mem sync status --blocked-details --json` returns all blocked/resolved details and proof availability; ordinary status keeps bounded 8-ID/8192-byte lists.

### §7.2.2. Blocked-history operator recovery

1. Parentless blocked tombstones lack lineage, not deletion history. Exact transactional-graveyard prior state permits **one immutable descendant pair per record**: prior-reaffirming put, then tombstone reaffirming original deletion intent. Existing parents/IDs/bytes and ancestry must remain unchanged; fake ancestors are forbidden.
2. **Each operation covers exactly one record.** A shared tombstone lets one late concurrent record change block the entire deletion (`blocked-concurrency`); its put lacks that concurrency check and survives, resurrecting another record without conflict. Pair-set atomicity does not replace this isolation.
3. Apply §7.2.1's per-record final-head judgment to the original blocked op: each record needs its sole safe effective tombstone or existing safe final put, truly descending it. If any fails, report the original active in full while retaining other records' safe deletion reports. Only diagnosis changes: fold classification/raw blocked set/reasons/counts/bodies/pending/history remain unchanged.
4. Read-only `plan` and explicit `apply --plan … --expect <plan_digest>` form the CAS surface. Plan exposes IDs/hashes/counts only, with no bodies on stdout, stderr or files. Neither leaf syncs remotely or calls a model. File output is new-only outside store/selected-snapshot hierarchy, published through a nofollow identity-bound parent; `--out -` is read-only. Embedded/computed/expected digests must agree, including retry.
   Plan reads actual serving rows and related local sync state in one read transaction; apply checks them in its writer transaction, preserving pending rows. Access recency cannot rewrite prior evidence. Only the six protocol set-list fields allow order/duplicate representation differences under strict string-array decoding; invalid JSON/types/different items refuse. Representation-only differences preserve raw serving rows and derived indexes. Plan still binds raw rows/full local state, so later physical changes invalidate it.
   Both leaves require supported active-v2 readiness, matching epoch/replica and completed cutover if a ledger exists; snapshots-sealed/legacy-capture refuses. Validate applicable producer evidence before binding it: fresh join seals original empty store/protected ref. After supported rotation, both fresh seals must match one member of the active replica's complete valid predecessor chain; missing/cyclic/malformed/foreign/split-producer proof refuses. Plan binds current replica and preserved lineage for later CAS. Snapshot activation seals verified equality and roster fence receipts. Missing/forged/merely digest-shaped fence proof refuses before plan and again inside apply; the plan also binds it. Cleanup needs the current regular staging file's device/inode and exact digest; changed temporaries stay with typed ownership conflict.
5. Apply takes the remote-exchange lock and rechecks every precondition in one `BEGIN IMMEDIATE`, recording the full pair set atomically. Never commit/publish a puts-only intermediate. This covers the single union-outbox publish path, not (2)'s concurrency isolation.
6. Before the writer funnel, pure-fold the complete new set: records/pending/unrelated frontiers/history/conflicts/outbox preserved, targets absent, every new op unblocked and single-record, every targeted blocked op resolved.
7. Recovery must not relax fold's blocked predicate, add wire kinds, alter completed `sync_migration_*` phases/evidence/seed reservations, or flip the writer fence.

### §7.3. Agent-Backed Mutation Boundary

Monitors surface candidates; semantic promotion/skip/merge/prune requires a user-directed post-it or agent-backed distiller/curator. Scripts enforce mechanical action/recovery contracts only.

#### D-43 — On-call incident-to-proposal bridge

Agent on-call loops may use bounded recent mutation events as incident leads. Read selected records fully and corroborate current source/tests/logs/artifacts/runtime before sending to the offline proposal inbox. Memory alone is insufficient and stays unchanged. The agent chooses a stable incident ID; code only matches it exactly, appends bounded recurrence under inbox lock and refuses ambiguous duplicates, without semantic equivalence inference. A named collector can create `observed` and advance through `reproduced` to `proposed` only. It cannot change reviewed/terminal decisions, impersonate human approval, edit source/runtime or activate realizations. This is bounded task work under D-42: no worker injection/curation/sync/consume/memory mutation.

### §7.4. Recall — On-Demand Retrieval

`mem inject` may summarize active non-conflicted working/durable/profile records at SessionStart. Every eligible main prompt probes only active current-project/global capsule FTS: at most six headline/ID candidates, 2,400 UTF-8 bytes. Conflicts expose bounded IDs/index, not provisional bodies. Probe is mechanical exposure, never adoption: no bodies/fallback, access updates, raw-prompt storage or lexical-hit truth. Its same-turn receipt proves only the retrieval opportunity. On hook failure/absence, use `mem recall-gate` for contextual `recall` (focused query) or `skip` (short reason). Retrieval does not consume handoffs. Telemetry stores bounded query/turn digests, result IDs/counts, bytes, gate decisions and later `applied|miss`, without raw prompts.

| Helper | Contract |
|---|---|
| `python3 <agent-home>/tools/memory/mem.py candidates <prompt> --session-id <id> [--turn-id <id>] [--hook]` | Main prompt bridge's bounded capsule probe and same-turn receipt above |
| `python3 <agent-home>/tools/memory/mem.py recall-gate --decision recall\|skip --reason <reason> [--query <query>]` | `recall` immediately searches active current-project/global memory; report hit with `--outcome applied --gate-id <id> --record-id <id>`, miss without record ID |
| `tools/memory/recall.sh "<query>" [--full] [--limit 1..100] [--all] [--sessions]` | Active capsule-first FTS5/BM25, body/CJK compatibility fallback then LIKE/`rg`; `mem recall` also supports exact `--topic` and explicit historical `--include-superseded` |
| `python3 <agent-home>/tools/memory/mem.py show <id> [--all]` | Known-ID metadata/exact multiline body; default active current-project/global, history via `--include-superseded` |
| `python3 <agent-home>/tools/memory/mem.py topics [topic]` | Active normalized topic/record navigation, not relevance classification |
| `tools/memory/index-check.sh [dir] [--fix]` | Legacy `projects/<cwd>/memory/MEMORY.md` missing/orphan pointer drift; fix appends missing pointers only, preserving curated lines; DB FTS5 belongs to `mem index` |

Only agents choose relevance; signal words, mandatory topics, prompt/category classifiers and thresholds cannot. Ignore unrelated hits. Read a relevant record fully before use; truncated/insufficient snippets require immediate `show <id>` or `recall --full --limit N`. Check claims against current code/artifacts. When a relevant memory names a file/artifact, read that target before reporting project state; missing/changed target means possible stale pointer, not permission to substitute remembered prose. Widen to history, cross-project/body/raw sessions only when useful; `--sessions` supplements curated memory with noisy undistilled transcripts. Direct SQLite/dump queries are not normal retrieval.

Simple searches run one or two `recall.sh` queries inline, then full bodies as needed. Deep raw-session/multi-angle/many-body/multi-directory searches use read-only **memory-scout**: narrow recall plus useful multilingual synonyms → hit IDs/a few full results → `--all` on miss → raw sessions → one-line live-code cross-check. Stay on the retrieval interface, without direct DB/dump reads or any write (`add`, `note`, `consume`, `restore`, `delete`, `reinforce`, `merge`, `prune`, file edits). Return ≤15 lines: present/absent/ambiguous verdict, ≤3 key quotations, IDs and one application instruction.

Per-cwd isolation is default; `--all` requires explicit cross-project need. Mass `--fix` mutates gitignored user `projects/` data and belongs to user-directed work; automation reports missing pointers without repairing them.

### §7.5. Mechanical Scaffold — Retrieval, Curation Candidates, and Pending Protection

Code exposes mechanical lifecycle candidates; deep curator chooses semantic actions, executed only after D-18/D-40 validation.

**D-40** supersedes automatic D-15/D-34 portions. Apply §7.4's probe/agent-adoption boundary: `mem candidates` owns tokenization, scope, ranking and limits only. Explicit `recall`/`recall.sh` deepen retrieval, `recall-gate` recovers opportunity; no deterministic prompt classification. `mem recall --auto` is retired; each active adapter registers fail-open `hooks/mem-recall-inject.sh`. `$XDG_STATE_HOME/agent-memory/recall-events.jsonl` is bounded raw-prompt-free telemetry; `recall-opportunities/` holds one atomic bounded receipt per hashed session. Search error creates no valid receipt; legitimate zero hits do. Main material mutation requires a current same-turn probe/recovery receipt; registered route-bound workers are exempt and skip main lifecycle.

**D-16 cleanup signals:** append `## 🧹 Cleanup signals` after `mem inject --hook` only when nonempty, inside SessionStart cap, default two lines. Cwd-scoped signals: durable near-duplicates, `durable > soft_ceiling=80`, working expiry within three days. Read-only, no deletes/flag writes/main housekeeping. D-18 session-end deep curator reads `curate-snapshot`/signals and emits action JSON for `mem-distill-dispatch.sh` allowlist/`shell=False` execution. This replaced D-17 main deletion: deep context and graveyard/dump recovery bound likely harm to inefficiency rather than loss.

**D-35 pending protection:** `delivery_state=ordinary|pending|consumed`. New handoffs and explicit `--requires-consume` threads are pending; normal transition requires `mem consume <id>`. Source upsert/body dedup preserves pending monotonically. Show/recall/full/inject do not consume. On `[pending:<id>]`, read full obligation → apply → verify → consume. Pending working records do not expire; their 21-day TTL restarts at consumption. `curate-snapshot` lists `PROTECTED PENDING`, excluding it from destructive `IDS:`. `prune`, `delete`, `merge`, `lifecycle --apply` recheck DB just before execution and refuse pending; any pending merge member aborts all strength/deletion changes. Graveyard retains action/canonical metadata for one-record `mem restore <id>`. Automatic consume is restricted to narrow pipeline/post-it paths naming the ID and proving application through artifacts.
